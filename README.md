За один проход выбрать не больше k самых дорогих, при равенстве - раньше поступившие. Хранить только выбранных кандидатов в куче размера не больше k, вершина -худший выбранный. В конце выдать ID по убыванию стоимости и порядку поступления.<br/>Стандартная сортировка выбранных разрешена; весь поток хранить или сортировать нельзя.<br/> В тестах проверить k = 0, k = 1, k больше числа заявок и равные стоимости. Объяснить, почему направление сравнения в ограниченной куче отличается от порядка ответа.<br/>Эталон: сортировка всего входа и срез.<br/>Где это встречается. Отбор самых дорогих заказов, самых медленных запросов или наиболее важных сообщений из большого потока. Ограниченная куча позволяет хранить только кандидатов в ответ; если стоимость заявки меняется после поступления, понадобится отдельно учитывать такие обновления. |   ❌    |
